## 1. Цель работы

Зафиксировать архитектуру системы учёта состояния сети:
определить сущности и ключи, спроектировать ER-модель,
описать HTTP-контракт между Vue и ASP.NET Core, показать,
почему браузер не обращается к PostgreSQL напрямую.

## 2. Исходные данные

Из ЛР1 взята предметная область: учёт повреждений кабеля
в АО «Компания ТрансТелеКом». Три критерия:
1. Диспетчер создаёт заявку.
2. Диспетчер назначает электромонтёра.
3. Электромонтёр переводит заявку в работу.

## 3. Ход работы

### 3.1. Архитектура
Построена схема из трёх узлов: Vue 3 (:5173) → ASP.NET Core
(:5000) → PostgreSQL (:5432). Прямой стрелки «браузер → БД»
нет — это принципиальное требование: серверные правила
нельзя обойти из клиента.

### 3.2. Модель данных
Выделены три сущности: CableTicket (главная), NetworkSite
(справочник), User (пользователь). Связи: один участок —
много заявок; один пользователь создаёт много заявок; один
электромонтёр может быть назначен на много заявок; у новой
заявки исполнитель отсутствует.

### 3.3. Проверка 3НФ
Название участка хранится один раз в NetworkSite; заявка
содержит только siteId. При переименовании участка меняется
одна строка.

### 3.4. Контракт API
Заполнена таблица: GET списка и одного элемента, POST
создания, два разных PATCH (assignee и status). DELETE
не используется — отмена через статус Cancelled.

### 3.5. Матрица требований
Три критерия ЛР1 связаны с полями модели и HTTP-запросами.
