ЛР1. Техническое задание

1. Предметная область

Заказчик: АО «Компания ТрансТелеКом», служба технического обслуживания сети.  
Процесс: Учёт повреждений кабеля и их устранение.

2. Как есть

Сейчас заявки на повреждение кабеля фиксируются диспетчером в бумажном журнале или в Excel. Факт повреждения теряется: неизвестно, кто взял заявку, в каком она состоянии. Электромонтёры узнают о задаче по телефону. Нет истории, нельзя посчитать, сколько времени ушло на устранение.

3. Как будет

Одна запись в системе — заявка на повреждение кабеля. Диспетчер создаёт её, указывая участок сети. Затем назначает электромонтёра. Электромонтёр видит только свои заявки, переводит их в работу и закрывает.

4. Граница

Внутри семестра:
- Создание заявки
- Назначение исполнителя
- Смена статуса (New → InProgress → Closed/Cancelled)
- Справочник участков сети
- Два экрана: список заявок, создание заявки
- Экран входа (роли)

Снаружи:
- Прогнозирование
- Интеграция с GIS, NMS
- Автоматический алертинг
- Мобильное приложение

7. Функциональные требования (8–15)

1. Диспетчер может создать заявку с заголовком, участком и описанием.
2. Диспетчер видит список всех заявок с их статусами.
3. Диспетчер может назначить электромонтёра на заявку.
4. Электромонтёр видит только назначенные ему заявки.
5. Электромонтёр может перевести заявку из New в InProgress.
6. Электромонтёр может закрыть заявку (InProgress → Closed).
7. Электромонтёр может отменить заявку (New → Cancelled).
8. Диспетчер может отменить заявку в статусе New.
9. Система хранит историю смены статусов.
10. При создании заявке присваивается уникальный номер.
11. Справочник участков сети доступен только для чтения.
12. Вход в систему по логину и паролю.

8. Нефункциональные требования (3–5)

1. Система работает в браузере Chrome/Firefox последних версий.
2. Время отклика API — не более 1 секунды.
4. Пароли хранятся в хешированном виде.
5. Данные сохраняются после перезапуска сервера.

9. Use case: Закрытие заявки

Актёр: Электромонтёр  
Предусловие: Заявка назначена на электромонтёра и находится в статусе InProgress.  
Основной поток:
1. Электромонтёр входит в систему.
2. Открывает список своих заявок.
3. Выбирает заявку в статусе InProgress.
4. Нажимает «Закрыть».
5. Система меняет статус на Closed.

Альтернатива: Заявка не в статусе InProgress → кнопка «Закрыть» недоступна.  
Постусловие: Статус заявки — Closed.

10. Три критерия

1. Создать
Дано: Диспетчер вошёл в систему.  
Когда: Заполняет заголовок (5–80), выбирает участок (> 0), описание (10–500), жмёт «Создать».  
Тогда: Заявка со статусом New и человеческим номером. ✅

2. Назначить
Дано: Диспетчер и заявка в статусе New.  
Когда: Назначает электромонтёра отдельным действием.  
Тогда: Исполнитель записан; статус пока New. ✅

4. В работу
Дано: Назначенный электромонтёр вошёл.  
Когда: Переводит свою заявку New → InProgress.  
Тогда: Статус «в работе»; чужой логин эту заявку не двигает. ✅

11. Четыре статуса

| Код в API/БД | Смысл | Подпись на экране |
|---|---|---|
| New | только создали | Новая |
| InProgress | исполнитель взял | В работе |
| Closed | сделали | Закрыта |
| Cancelled | отменили | Отменена |
